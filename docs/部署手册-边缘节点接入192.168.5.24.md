# 第二部分：边缘/工位执行节点（ate-platform）接入 .24

> 对应计划任务：breakpoint-fmea-architecture **Task 33** — Configure the local edge/execution node
> 配套文件：配置模板 [`config/edge-node.env.example`](../config/edge-node.env.example)、
> 启动脚本 [`scripts/deploy/run_edge_worker.sh`](../scripts/deploy/run_edge_worker.sh)、
> 边缘入口模块 `src/ate_platform/scheduler/edge_worker.py`（`python -m ate_platform.scheduler.edge_worker`）。

## 8. 边缘节点定位与架构

- **服务器 192.168.5.24** 运行**云端**：ate-cloud（:8000 / nginx :80）、NATS JetStream（:4222，
  监控 :8222）、Qdrant（:6333）、PostgreSQL。
- **工位/执行节点（本机，Windows 或 Linux）** 运行 **ate-platform** 边缘执行引擎：
  `JetStreamWorker` 从 .24 的 NATS 拉取测试任务、执行 YAML 计划、回传状态、接收控制命令。
- **边缘不连 PostgreSQL、不跑数据库服务**：边缘本地状态只有
  - 一个持久化 **worker_id**（NATS KV 注册身份）；
  - 可选的**崩溃恢复快照**（§6.6）；
  - **本地 SQLite** 离线缓存（断网缓冲、重连回传，WAL 模式）。

消息走向：

```
工位机 (ate-platform / edge_worker)                192.168.5.24 (云端)
  JetStreamWorker ──拉任务──►  NATS JetStream  ◄── ate-cloud 下发任务
    │  ate.tasks.*  (durable: ate-worker)
    │  心跳/注册 ──► KV bucket: ate-workers (workers.<worker_id>, 15s)
    │  状态/断点命中 ──► ate.status.<run_id>  ──► 云端 SSE / 前端
    │  ◄── 控制命令 ── ate.control.<run_id>
    │     abort / pause / resume / force_next
    │     step_control(over/into/out/run_to_cursor)
    │     inject_fault / sync_breakpoints
  本地 SQLite（~/.ate_platform 或 ATE_PLATFORM_DATA_DIR）
```

## 8.1 前置条件

1. 工位机已安装 **Python 3.12+** 与 [uv](https://docs.astral.sh/uv/)（仓库 `uv sync` 可用即可）；
2. 已拿到 ATEStudio 代码（git clone / 拷贝），位于工位机本地目录；
3. 工位机能访问 .24 的 NATS 端口（调试网段内一般默认可达）：
   ```bash
   # 监控页应能打开（返回 JSON）
   curl http://192.168.5.24:8222/varz
   ```
   Windows PowerShell：`curl.exe http://192.168.5.24:8222/varz`（或浏览器直接打开）；
4. **不需要任何真实仪器**——本节点以仿真模式运行（虚拟 DMM/PSU）。

> 实际对 .24 的在线联调（真发任务、断点暂停/恢复冒烟）属于 **Task 34 的人工/在线闸门**；
> 本节交付**可运行的配置 + 启动方式 + 文档**，在 Task 34 用 `smoke_live.sh` 统一验收。

## 8.2 配置（只填占位符，无密钥）

复制模板并填写（模板只有内网地址与 `<占位符>`，**不含任何密码/密钥**）：

- **Linux / WSL / Git-Bash：**
  ```bash
  cp config/edge-node.env.example config/edge.env
  # 编辑 config/edge.env：把 <EDGE_DATA_DIR>、<STATION_ID> 换成真实值
  ```
- **Windows PowerShell（直接设进程级环境变量即可）：**
  ```powershell
  $env:ATE_PLATFORM_NATS_URL = "nats://192.168.5.24:4222"
  $env:ATE_SIMULATION_MODE   = "true"
  $env:ATE_PLATFORM_DATA_DIR = "C:/ate/edge-data"      # 本地状态 + SQLite 缓存目录
  $env:ATE_PLATFORM_STATION_ID = "STATION-DEBUG-01"    # 工位标识（运维命名）
  ```

边缘节点环境变量一览：

| 变量 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `ATE_PLATFORM_NATS_URL` | 是 | `nats://localhost:4222` | 云端 NATS，调试环境固定 `nats://192.168.5.24:4222`（Task 33 新增的边缘覆盖项；缺省与旧默认完全一致） |
| `ATE_SIMULATION_MODE` | 是 | `false` | `true` = 虚拟仪器（MockDriverFactory），不接硬件 |
| `ATE_PLATFORM_DATA_DIR` | 是 | `~/.ate_platform` | 边缘本地状态目录：worker_id、SQLite 缓存、快照 |
| `ATE_PLATFORM_STATION_ID` | 建议 | 无 | 工位/站点标识（执行记录 `station_id`、运维命名） |
| `ATE_PLATFORM_SNAPSHOT_DIR` | 否 | 空（禁用） | 崩溃恢复快照目录（§6.6），一般设为 `<数据目录>/snapshots` |
| `ATE_PLATFORM_NATS_FILE_STORE_ENABLED` | 否 | `true` | JetStream 文件存储事件缓冲（断网不丢事件） |

> worker_id 由入口模块固定写到 `<ATE_PLATFORM_DATA_DIR>/worker_id`（重启复用同一身份）。

## 8.3 启动边缘 worker

**模块入口（推荐，Windows / Linux 通用）：**

```bash
# 仓库根目录，先让 src 可导入
export PYTHONPATH=src          # Windows PowerShell: $env:PYTHONPATH="src"
uv run python -m ate_platform.scheduler.edge_worker
```

**或用启动脚本（Linux / WSL / Git-Bash，自动 source env 文件、校验占位符、建数据目录）：**

```bash
chmod +x scripts/deploy/run_edge_worker.sh     # Windows 检出会丢 +x 位
scripts/deploy/run_edge_worker.sh config/edge.env
```

启动成功（NATS 可达）时日志类似：

```
INFO __main__: Starting edge worker (nats_url=nats://192.168.5.24:4222, data_dir=..., simulation=True)
INFO ate_platform.scheduler.edge_worker: Edge worker <uuid> connected to nats://192.168.5.24:4222; waiting for tasks
INFO ate_platform.scheduler.jetstream_worker: JetStreamWorker <uuid> started
```

随后 worker 以 30s 超时循环拉取 `ate.tasks.*` 任务；无任务时安静等待，有任务则引导
`ScannerScheduler` 执行计划。`Ctrl-C` 停止。

## 8.4 仿真模式（无硬件）

`ATE_SIMULATION_MODE=true` 时，测试脚本/驱动通过 `MockDriverFactory` 使用**虚拟仪器**
（DMM/PSU 等对 SCPI 返回模拟值），工位机**不需要接 GPIB/LAN 仪器**。这与 Docker dev
profile、`examples/` 示例的默认行为一致。只有产线正式接真仪器时才设为 `false`。

## 8.5 本地 SQLite 缓存（边缘绝不用 PostgreSQL）

`<ATE_PLATFORM_DATA_DIR>` 下的边缘本地数据：

| 路径 | 内容 | 模块 |
|------|------|------|
| `worker_id` | 持久化 worker 身份（KV 注册） | `jetstream_worker` |
| `snapshots/`（可选） | 崩溃恢复状态快照（RUNNING/PENDING 回退重跑） | §6.6 `state_snapshot` |
| `sqlite/edge-cache.db` | 离线版本缓存（序列/拓扑，ACK 门控、SHA256 校验） | `ate_platform.offline.cache_store.OfflineCacheStore` |
| `sqlite/uploads.db` | 待上传执行记录队列（`pending→uploaded→acked`，WAL） | `ate_platform.offline.upload_queue.UploadQueue` |

- SQLite 以 **WAL** 模式打开（`journal_mode=WAL / synchronous=NORMAL / busy_timeout=30000`），
  库文件在首次使用时**自动创建**，无需手工建库；
- 断网时执行记录进入本地队列缓冲，重连后由对账（reconciliation）批量回传、云端 ACK 后保留 7 天清理；
- 边缘**不配置也不需要 PostgreSQL/MySQL**——关系型数据库是云端的事。

## 8.6 断点与控制消息在 NATS 上的流转

任务 18（DSL `breakpoint` 步骤）与任务 20（边缘自评估断点）落地后，断点/控制完全走 NATS：

1. **任务下发**：云端把 YAML 计划发到 JetStream 主题 `ate.tasks.*`（durable 消费者 `ate-worker`）；
   断点定义可随任务 payload 的 `breakpoints: [...]` 字段一并下发。
2. **断点同步（云端 → 边缘）**：云端发控制消息
   `{"action":"sync_breakpoints","breakpoints":[...]}` 到 `ate.control.<run_id>`；
   边缘 `parse_breakpoint_defs` 容错解码（畸形条目丢弃计数、绝不挂起），武装/热更新
   `EdgeBreakpointEngine`。执行前到达则暂存（`phase:"pending"`），执行中到达则热武装（`phase:"active"`），
   并经 request-reply 回 `{status:ok, armed, dropped, phase}`。
3. **命中断点（边缘 → 云端）**：计划执行到 DSL `breakpoint` 步骤（或满足 `condition` 条件）时，
   边缘**自评估命中**，发布 `BREAKPOINT_HIT` 事件（含变量快照）并转发到 `ate.status.<run_id>`，
   然后在**既有暂停门**上挂起（与 T39/T40 pause/step、任务 18 的 hook 同一个 `_pause_event` 门）。
   云端不需要逐条驱动暂停。
4. **暂停/恢复（云端 → 边缘）**：云端发 `{"action":"pause"}` / `{"action":"resume"}`
   （以及 `abort` / `force_next` / `step_control` / `inject_fault`）到 `ate.control.<run_id>`；
   `resume` 释放暂停门，计划继续。步进调试用 `step_control`（`over/into/out/run_to_cursor`）。
5. **状态回传**：步骤生命周期事件（STEP_STARTED/COMPLETED/FAILED/SKIPPED/STATUS_CHANGED）与
   `BREAKPOINT_HIT` 统一转发到 `ate.status.<run_id>`，供云端 SSE/前端实时展示。

> 在 NATS 监控页 http://192.168.5.24:8222 可查看连接、JetStream 流与 `ate-workers` KV。

## 8.7 排错

| 现象 | 原因 / 处理 |
|------|-------------|
| 日志反复 `Edge worker NATS connect to nats://192.168.5.24:4222 failed (...) — retrying in 5s`，**进程不退出** | .24 NATS 不可达或网络不通。这是**预期的 fail-soft 行为**：worker 每 5s 干净重试、绝不崩溃；确认 .24:4222 可达（`curl http://192.168.5.24:8222/varz`）、防火墙放行后即自动连上 |
| 启动脚本报 `still contains a placeholder ...` 并退出码 2 | `config/edge.env` 里 `<EDGE_DATA_DIR>` / `<STATION_ID>` 等占位符没替换；填好再启动 |
| `ModuleNotFoundError: ate_platform` | 没设 `PYTHONPATH=src`（脚本会自动设；手工运行需先 `export PYTHONPATH=src`） |
| 连接真实仪器报错 / 找不到 VISA 设备 | 仿真模式应为 `ATE_SIMULATION_MODE=true`；无硬件时勿设 `false` |
| 工位在 NATS 监控页看不到 | 确认 worker 日志已 `connected`；KV bucket 为 `ate-workers`，key 为 `workers.<worker_id>`；worker_id 文件在 `<数据目录>/worker_id` |
| 断网期间任务状态 | 事件走 JetStream 文件存储缓冲、执行记录进本地 SQLite 队列；恢复网络后自动重连/回传，不丢数据 |
| 想重置工位身份 | 删除 `<数据目录>/worker_id` 后重启，会生成新 UUID（旧 KV 条目由云端按心跳过期清理） |
