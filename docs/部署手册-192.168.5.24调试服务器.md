# 部署手册：192.168.5.24 调试服务器（FalkorDB 开通）

> 对应计划任务：breakpoint-fmea-architecture **Task 31** — Provision FalkorDB on 192.168.5.24
> 配套脚本：[`scripts/deploy/provision_falkordb.sh`](../scripts/deploy/provision_falkordb.sh)
> 设计依据：系统设计文档 §10 部署架构（§10.2 已在 .24 验证 Podman Compose 兼容）。

本手册说明如何在调试服务器 **192.168.5.24** 上开通 **FalkorDB** 图数据库（替代已退役的
Neo4j；FalkorDB 走 **Redis 协议 RESP / 6379**，不是 Bolt/7687），并汇总该服务器上
**已经在运行** 的 NATS、Qdrant 等服务端点，供集成测试与后续云端部署（Task 32/34）使用。

---

## 1. 人工/SSH 闸门（重要）

开通脚本必须**在 .24 本机执行**（或由能登录 .24 的人执行）。自动化 Agent **无法**
非交互式 SSH 登录该服务器：

```
$ ssh chenp@192.168.5.24
Permission denied (publickey,password).
```

因此本任务交付物是**脚本 + 手册**；实际执行是人工闸门（human gate）：

- 请由持有 .24 SSH 密钥/密码或控制台权限的同事，按第 3 节操作；
- 执行完成后把脚本输出贴回，Task 34 的在线全链路冒烟（`smoke_live.sh`）才能跑通；
- 在开通之前，Agent 侧的 `tests/integration` 集成套件会因 6379 不可达而**干净跳过**（SKIP），不影响默认门禁。

## 3. 开通步骤（在 .24 上执行）

```bash
# 1) 把仓库代码放到 .24（任选：git clone / scp / U 盘拷贝均可）
cd /opt/ATEStudio   # 或任意放代码的目录

# 2) 赋予可执行权限（Windows 检出会丢失 +x 位，必须 chmod）
chmod +x scripts/deploy/provision_falkordb.sh

# 3) 执行（需要 root：写 /var/lib 或起宿主端口 <1024 不涉及，但容器/系统服务需要权限）
sudo ./scripts/deploy/provision_falkordb.sh
```

脚本是**幂等**的，可随时重复执行。成功时末尾输出：

```
[provision-falkordb] PASS: Redis PING -> PONG (127.0.0.1:6379)
[provision-falkordb] PASS: openCypher GRAPH.QUERY fmea "RETURN 1" -> 1
[provision-falkordb] FalkorDB is ready:
[provision-falkordb]   RESP (Redis protocol): redis://192.168.5.24:6379
[provision-falkordb]   Browser UI           : http://192.168.5.24:3000
```

重复执行时若已在运行，直接 no-op 成功退出：

```
[provision-falkordb] FalkorDB already running and answering PING on port 6379 — nothing to do.
```

### 3.1 脚本做了什么

按顺序自动选择安装方式（**先 podman，再 docker，最后裸机**）：

1. **已运行快速路径**：6379 能 PING 通 → 打印 "already running"，退出 0，什么都不改；
2. **容器路径（.24 预期走这里）**：检测到 `podman`（设计文档 §10.2 已验证 .24 有 Podman）
   或 `docker` → 拉取 `falkordb/falkordb:latest` → 以固定名 **容器 `falkordb`**、
   **具名卷 `falkordb-data`（挂载到容器内 `/data`）** 启动，端口映射
   `6379:6379` + `3000:3000`，`--restart unless-stopped`，并开启 AOF 持久化
   （`--appendonly yes --appendfsync everysec`）。旧同名容器会被删除重建，**数据卷保留**；
3. **裸机兜底**：没有容器运行时时，下载官方预编译模块
   `falkordb-x64.so`（GitHub Release，默认 v4.20.4）到 `/var/lib/falkordb/`，
   用宿主机 **redis-server ≥ 8.0**（FalkorDB 4.x 要求 Redis 8，7.x 不支持）加载
   `loadmodule` 启动，优先写成 **systemd 服务 `falkordb`**（无 systemd 时 nohup）。
   裸机方式没有 Browser UI（3000）。
4. **验证**：等待端口 → `redis-cli PING`（期望 PONG）→ `GRAPH.QUERY fmea "RETURN 1"`
   （openCypher 冒烟，期望返回整数 1），打印 PASS/FAIL。

### 3.2 可选环境变量

| 变量 | 默认 | 用途 |
|------|------|------|
| `FALKORDB_PASSWORD` | 空（调试网段无密码） | 设置后容器/裸机均启用 `--requirepass`，验证命令自动带 `-a` |
| `FALKORDB_PORT` | `6379` | RESP 端口 |
| `FALKORDB_UI_PORT` | `3000` | Browser UI 端口（容器方式） |
| `FALKORDB_CONTAINER` / `FALKORDB_VOLUME` | `falkordb` / `falkordb-data` | 固定名，保证幂等 |
| `FALKORDB_VERSION` | `v4.20.4` | 裸机模块版本 |
| `FALKORDB_DATA_DIR` | `/var/lib/falkordb` | 裸机数据/模块目录 |

> 调试服务器位于内网调试网段，默认**不设密码**（与现有 NATS/Qdrant 一致）；
> 若要加密码，用 `sudo FALKORDB_PASSWORD='<强密码>' ./provision_falkordb.sh`，
> 并同步更新云端 `.env` 的 `FALKORDB_URL=redis://:<密码>@192.168.5.24:6379`
> （Task 32 的 `env.24.template` 只放占位符，真实密码只存在服务器上，**不得提交仓库**）。

## 5. 无容器运行时时的人工安装指引

脚本检测到 podman/docker/redis-server **全都没有**时，不会报晦涩错误，而是打印明确指引后退出。
.24 上建议直接装 Podman（与 §10.2 一致）：

```bash
# RHEL / CentOS / Rocky / openEuler 系
sudo dnf install -y podman
# Debian / Ubuntu 系
sudo apt-get update && sudo apt-get install -y podman
```

裸机方式需要 **Redis 8.0+**（Redis 7.x 不被 FalkorDB 4.x 支持）与 OpenMP 运行库：

```bash
sudo dnf install -y redis redis-cli libgomp      # RHEL 系
sudo apt-get install -y redis-server redis-tools libgomp1   # Debian 系
```

## 6. 日常运维与排错

```bash
# 容器方式
sudo podman ps                         # 看到 falkordb 容器 Up
sudo podman logs --tail 100 falkordb   # 日志
sudo podman restart falkordb           # 重启（数据在 falkordb-data 卷，不丢）
sudo podman volume inspect falkordb-data

# 裸机方式
systemctl status falkordb
journalctl -u falkordb -n 100
ls -l /var/lib/falkordb/               # falkordb.so / falkordb.conf / 数据(AOF+RDB)

# 重新执行脚本永远安全：已运行则 no-op；容器被删/停会重建并复用数据卷；
# 裸机模块已下载则复用（删除 /var/lib/falkordb/falkordb.so 可强制重新下载）。
```

| 现象 | 排查 |
|------|------|
| 脚本拉镜像失败 | 内网离线时若本地已有缓存镜像会继续；否则先 `podman pull falkordb/falkordb:latest` 或配置镜像加速 |
| PING 不通 | `podman logs falkordb` / `journalctl -u falkordb`；确认 .24 防火墙放行 6379（`firewall-cmd --add-port=6379/tcp --permanent && firewall-cmd --reload`） |
| 裸机模块加载失败 `libgomp.so.1` | 装 OpenMP：`dnf install -y libgomp` 或 `apt-get install -y libgomp1` |
| 裸机报 Redis 版本过低 | FalkorDB 4.x 需 Redis 8.0+；升级 Redis 或改用 Podman 路径 |
| 3000 UI 打不开 | 仅容器方式提供；裸机方式无 UI；检查防火墙放行 3000 |

# 第二部分：边缘/工位执行节点（ate-platform）接入 .24

> 对应计划任务：breakpoint-fmea-architecture **Task 33** — Configure the local edge/execution node
> 配套文件：配置模板 [`config/edge-node.env.example`](../config/edge-node.env.example)、
> 启动脚本 [`scripts/deploy/run_edge_worker.sh`](../scripts/deploy/run_edge_worker.sh)、
> 边缘入口模块 `src/ate_platform/scheduler/edge_worker.py`（`python -m ate_platform.scheduler.edge_worker`）。

## 8. 边缘节点定位与架构

- **服务器 192.168.5.24** 运行**云端**：ate-cloud（:8000 / nginx :80）、NATS JetStream（:4222，
  监控 :8222）、Qdrant（:6333）、FalkorDB（:6379，Task 31 开通）。
- **工位/执行节点（本机，Windows 或 Linux）** 运行 **ate-platform** 边缘执行引擎：
  `JetStreamWorker` 从 .24 的 NATS 拉取测试任务、执行 YAML 计划、回传状态、接收控制命令。
- **边缘不连 PostgreSQL、不跑数据库服务**：边缘本地状态只有
  - 一个持久化 **worker_id**（NATS KV 注册身份）；
  - 可选的**崩溃恢复快照**（§6.6）；
  - **本地 SQLite** 离线缓存（断网缓冲、重连回传，WAL 模式）。

消息走向：

```
工位机 (ate-platform / edge_worker)                192.168.5.24 (云端)
  JetStreamWorker ──拉任务──►  NATS JetStream  ◄── ate-cloud 下发任务
    │  ate.tasks.*  (durable: ate-worker)
    │  心跳/注册 ──► KV bucket: ate-workers (workers.<worker_id>, 15s)
    │  状态/断点命中 ──► ate.status.<run_id>  ──► 云端 SSE / 前端
    │  ◄── 控制命令 ── ate.control.<run_id>
    │     abort / pause / resume / force_next
    │     step_control(over/into/out/run_to_cursor)
    │     inject_fault / sync_breakpoints
  本地 SQLite（~/.ate_platform 或 ATE_PLATFORM_DATA_DIR）
```

## 8.1 前置条件

2. 已拿到 ATEStudio 代码（git clone / 拷贝），位于工位机本地目录；
3. 工位机能访问 .24 的 NATS 端口（调试网段内一般默认可达）：
   ```bash

   curl http://192.168.5.24:8222/varz
   ```
   Windows PowerShell：`curl.exe http://192.168.5.24:8222/varz`（或浏览器直接打开）；
4. **不需要任何真实仪器**——本节点以仿真模式运行（虚拟 DMM/PSU）。

> 实际对 .24 的在线联调（真发任务、断点暂停/恢复冒烟）属于 **Task 34 的人工/在线闸门**；
> 本节交付**可运行的配置 + 启动方式 + 文档**，在 Task 34 用 `smoke_live.sh` 统一验收。

## 8.2 配置（只填占位符，无密钥）

复制模板并填写（模板只有内网地址与 `<占位符>`，**不含任何密码/密钥**）：

| 变量 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `ATE_PLATFORM_NATS_URL` | 是 | `nats://localhost:4222` | 云端 NATS，调试环境固定 `nats://192.168.5.24:4222`（Task 33 新增的边缘覆盖项；缺省与旧默认完全一致） |

## 8.4 仿真模式（无硬件）

`ATE_SIMULATION_MODE=true` 时，测试脚本/驱动通过 `MockDriverFactory` 使用**虚拟仪器**
（DMM/PSU 等对 SCPI 返回模拟值），工位机**不需要接 GPIB/LAN 仪器**。这与 Docker dev
profile、`examples/` 示例的默认行为一致。只有产线正式接真仪器时才设为 `false`。

## 8.5 本地 SQLite 缓存（边缘绝不用 PostgreSQL）

`<ATE_PLATFORM_DATA_DIR>` 下的边缘本地数据：

| 路径 | 内容 | 模块 |
|------|------|------|
| `worker_id` | 持久化 worker 身份（KV 注册） | `jetstream_worker` |
| `snapshots/`（可选） | 崩溃恢复状态快照（RUNNING/PENDING 回退重跑） | §6.6 `state_snapshot` |
| `sqlite/edge-cache.db` | 离线版本缓存（序列/拓扑，ACK 门控、SHA256 校验） | `ate_platform.offline.cache_store.OfflineCacheStore` |
| `sqlite/uploads.db` | 待上传执行记录队列（`pending→uploaded→acked`，WAL） | `ate_platform.offline.upload_queue.UploadQueue` |

- SQLite 以 **WAL** 模式打开（`journal_mode=WAL / synchronous=NORMAL / busy_timeout=30000`），
  库文件在首次使用时**自动创建**，无需手工建库；
- 断网时执行记录进入本地队列缓冲，重连后由对账（reconciliation）批量回传、云端 ACK 后保留 7 天清理；
- 边缘**不配置也不需要 PostgreSQL/MySQL**——关系型数据库是云端的事。

## 8.6 断点与控制消息在 NATS 上的流转

任务 18（DSL `breakpoint` 步骤）与任务 20（边缘自评估断点）落地后，断点/控制完全走 NATS：

1. **任务下发**：云端把 YAML 计划发到 JetStream 主题 `ate.tasks.*`（durable 消费者 `ate-worker`）；
   断点定义可随任务 payload 的 `breakpoints: [...]` 字段一并下发。
2. **断点同步（云端 → 边缘）**：云端发控制消息
   `{"action":"sync_breakpoints","breakpoints":[...]}` 到 `ate.control.<run_id>`；
   边缘 `parse_breakpoint_defs` 容错解码（畸形条目丢弃计数、绝不挂起），武装/热更新
   `EdgeBreakpointEngine`。执行前到达则暂存（`phase:"pending"`），执行中到达则热武装（`phase:"active"`），
   并经 request-reply 回 `{status:ok, armed, dropped, phase}`。
3. **命中断点（边缘 → 云端）**：计划执行到 DSL `breakpoint` 步骤（或满足 `condition` 条件）时，
   边缘**自评估命中**，发布 `BREAKPOINT_HIT` 事件（含变量快照）并转发到 `ate.status.<run_id>`，
   然后在**既有暂停门**上挂起（与 T39/T40 pause/step、任务 18 的 hook 同一个 `_pause_event` 门）。
   云端不需要逐条驱动暂停。
4. **暂停/恢复（云端 → 边缘）**：云端发 `{"action":"pause"}` / `{"action":"resume"}`
   （以及 `abort` / `force_next` / `step_control` / `inject_fault`）到 `ate.control.<run_id>`；
   `resume` 释放暂停门，计划继续。步进调试用 `step_control`（`over/into/out/run_to_cursor`）。
5. **状态回传**：步骤生命周期事件（STEP_STARTED/COMPLETED/FAILED/SKIPPED/STATUS_CHANGED）与
   `BREAKPOINT_HIT` 统一转发到 `ate.status.<run_id>`，供云端 SSE/前端实时展示。

> 在 NATS 监控页 http://192.168.5.24:8222 可查看连接、JetStream 流与 `ate-workers` KV。

## 8.7 排错

| 现象 | 原因 / 处理 |
|------|-------------|
| 日志反复 `Edge worker NATS connect to nats://192.168.5.24:4222 failed (...) — retrying in 5s`，**进程不退出** | .24 NATS 不可达或网络不通。这是**预期的 fail-soft 行为**：worker 每 5s 干净重试、绝不崩溃；确认 .24:4222 可达（`curl http://192.168.5.24:8222/varz`）、防火墙放行后即自动连上 |
| 启动脚本报 `still contains a placeholder ...` 并退出码 2 | `config/edge.env` 里 `<EDGE_DATA_DIR>` / `<STATION_ID>` 等占位符没替换；填好再启动 |
| `ModuleNotFoundError: ate_platform` | 没设 `PYTHONPATH=src`（脚本会自动设；手工运行需先 `export PYTHONPATH=src`） |
| 连接真实仪器报错 / 找不到 VISA 设备 | 仿真模式应为 `ATE_SIMULATION_MODE=true`；无硬件时勿设 `false` |
| 工位在 NATS 监控页看不到 | 确认 worker 日志已 `connected`；KV bucket 为 `ate-workers`，key 为 `workers.<worker_id>`；worker_id 文件在 `<数据目录>/worker_id` |
| 断网期间任务状态 | 事件走 JetStream 文件存储缓冲、执行记录进本地 SQLite 队列；恢复网络后自动重连/回传，不丢数据 |
| 想重置工位身份 | 删除 `<数据目录>/worker_id` 后重启，会生成新 UUID（旧 KV 条目由云端按心跳过期清理） |
