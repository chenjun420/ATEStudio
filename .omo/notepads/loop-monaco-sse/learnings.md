## Task 3.1 - Loop Container Execution Engine
- Created `src/ate_platform/executor/loop_executor.py` — LoopExecutor class with `async execute_loop(loop, run_id)` method
  - 3 loop types: FOR (count-based), WHILE (condition-based), FOREACH (collection-based)
  - Serial mode: iterate sequentially, each iteration waits for previous
  - Parallel mode: uses ProcessExecutor.execute_batch() with asyncio.Semaphore for concurrency control
  - Publishes LOOP_ITERATION_STARTED/COMPLETED events via EventBus
  - Each iteration gets its own scope in VariableSpace: `loop.<loop_id>.<iteration>.<key>`
  - FOR loop: iteration variable (default "i") set to current index (0..count-1)
  - WHILE loop: evaluates condition via _evaluate_condition_expr() before each iteration; max_iterations safety limit (default 1000)
  - FOREACH loop: resolves collection from VariableSpace, iterates over items, sets iteration_var to current item
  - Results: accumulates LoopIterationResult for each iteration into LoopResult
  - Nested loops supported: YamlLoop steps within a loop are executed recursively via a new LoopExecutor instance
- Added `LoopIterationResult` and `LoopResult` dataclasses to `src/shared/types.py`
  - LoopIterationResult: iteration (int), status (StepStatus), outputs (dict), error (str|None), duration (float)
  - LoopResult: loop_id (str), loop_type (str), total_iterations (int), passed (int), failed (int), iteration_results (list), status (StepStatus), duration (float), error (str|None)
  - Both exported via shared/__init__.py and ate_platform/types.py
- Modified `src/ate_platform/scheduler/variable_space.py` — added loop scope as 4th scope
  - WRITABLE_SCOPES expanded from {"scope", "steps"} to {"scope", "steps", "loop"}
  - Internal storage: `self._loop: dict[str, dict[str, Any]]` — keyed by loop_id, then by remaining path (e.g., "0.i", "result")
  - get() handles `loop.<loop_id>.<remaining_path>` with flexible path parsing
  - set() handles `loop.<loop_id>.<remaining_path>` with validation
  - Convenience methods: set_loop_variable(loop_id, iteration, key, value), get_loop_variable(loop_id, iteration, key, default), get_loop_result(loop_id), clear_loop()
  - resolve() regex pattern updated from `[a-zA-Z_][a-zA-Z0-9_]*` to `[a-zA-Z0-9_]+` for post-dot segments to support numeric iteration indices (e.g., `${loop.test.0.value}`)
- Modified `src/ate_platform/scheduler/scanner_scheduler.py` — loop-aware step scanning
  - Added `execute_loop_step(loop, run_id)` method: creates LoopExecutor, marks loop RUNNING in registry, executes, updates registry with final status
  - Lazily creates ProcessExecutor via `_get_or_create_executor()` for loop execution
  - Loop results stored in VariableSpace under `loop.<loop_id>.result` (done by LoopExecutor)
- Test count: 451 → 472 (21 new tests in test_loop_executor.py)
  - FOR loop serial (3 iterations), iteration variable, custom iteration var
  - FOR loop parallel (3 iterations, max_concurrency=2), parallel iteration vars
  - WHILE loop with condition, executes when true, max_iterations safety
  - FOREACH loop with string/int collection, missing collection error
  - Empty loop (0 count, None count, false condition)
  - Variable scoping (result stored, get/set, direct access, resolve)

- Key design decisions:
  - Loop scope uses flat dict per loop_id with "iteration.key" as sub-keys (not nested dicts) — simpler implementation, works with existing get/set pattern
  - WHILE condition evaluation uses VariableSpace.resolve() for ${} substitution + safe eval() for boolean expressions — no dependency on ConditionEvaluator's Condition dataclass
  - Parallel mode pre-sets all iteration variables before launching batch, since execute_batch() runs all tasks concurrently
  - LoopExecutor stores result in VariableSpace automatically after execution — no separate step needed
  - ScannerScheduler's execute_loop_step() is a public async method that can be called when a YamlLoop step is encountered during plan execution
